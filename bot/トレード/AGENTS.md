## 触らないもの（理由つき）

- **場所と名前を変えない**: `トレード/forward/`・`トレード/執行/`・`自動実行/`・`lab-ops/` の中のフォルダとファイル。上の常駐は絶対パスで呼ぶ。`forward/S21/凍結/記録用コード_hashes.json`（帳簿）はパスを鍵にしてハッシュを持つ。`執行/deploy.py` はワークスペースからの相対パスのまま winnote へ配る。`forward/common.py` は自分の場所の深さから `検証/` を決める。
- **凍結したものを変えない**: `forward/*/凍結/` のモデルと json、帳簿に載っている記録用コード。記録の値打ちは「凍結から変えていない」ことにある。変えるなら帳簿に「修正 N」を足し、売買の計算への影響を確かめる。
- **`*.orig_*`・`*.bak_*` を片付けない**: パッチの戻し先。`自動実行/ログ/*/パッチ_*/戻す.sh` が今の場所を当てにしている。
- **winnote の bot・MT5・タスクに触れない。デモへの注文をしない。** 実弾は卒業まで 0。
- **taichi だけが変えるもの**: `bot要件_凍結_20261105.md`・関門の値・運用規程。
- **外への出し方（2026-11-20 に変更）**: bot 制作は公開する（taichi「公開で進めて」）。出すのは `発信/GitHub/写しを作る.py` が作る写し `発信/GitHub/fx-bot/` だけで、push は taichi が中身を見た後（公開先: https://github.com/tai-chii/systrade-lab ・2026-11-20 に最初の push。次からも毎回 taichi の承認の後）。モデルの本体・口座と鍵・winnote から届く状態・価格データ・ログは入れない。写しに入らないもの（新しい検証で効いた結果・記事・外部の AI への貼り付け）は今までどおり出さない（`_基盤/CLAUDE.md` の「勝てそうなロジックの秘匿」）。

## 直しの入れ方

- 無人の回は本物を書き換えない。パッチ（`入れる.sh`・`戻す.sh`・試験つき）を作り、判断待ちに推奨つきで出す。
- 対話で taichi が承認した変更は入れてよい。規則・判断・記録用コードを変えたら `forward/変更履歴.csv` に 1 行、記録用コードなら帳簿に「修正 N」も足す。
- 判断待ちの正本は `自動実行/判断待ち_一覧.md`（2026-11-19 にログの中から移した）。
- `自動実行/要対応.md` は未解決と直近の節だけ。解決済みの古い節は `自動実行/要対応_過去/要対応_YYYY-MM.md`（`自動実行/要対応を割る.py` が移す。毎朝の要対応ページは両方を読む）。

## 用語

| 言葉 | 意味 |
|---|---|
| S 番号 | 戦略（bot）1 本 |
| Q 番号 | 検証 1 件（問い 1 つ）。フォルダ名の末尾の `-q515` など |
| R | 1 回の取引で取るリスクを 1 とした損益 |
| ★ | taichi の判断が要るもの（`要対応.md`） |
| 判断待ち N | `判断待ち_一覧.md` の番号 |
| 修正 N | 記録用コードの変更の通し番号（帳簿） |
| 記録のフォワード（仮想フォワード） | 注文を出さず、凍結した規則で未来の相場の売買を計算して残す |
| 実行 bot | デモ口座で実際に注文する bot（今は S21。S23 は dry） |
| 観察枠 | 関門に届かないが知りたいことがある戦略を、成績を数えずに記録する 2 枠（規程 §8） |
| dry / live | 発注しない／発注する（どちらもデモ口座） |
| 封印期間 | 事前登録で「読まない」と決めた最後の期間。taichi の承認の後に 1 回だけ読む |
