## 記録との同等性（2026-10-28・偽 MT5 で確認）

Dukascopy の足を「サーバー時間 EET・bid＋spread」の MT5 風に返す偽 `MetaTrader5` モジュール（クラウドのテスト用・配布しない）で `execute_mt5.py` を 1 時間ずつ回し、`forward_s21.py` の記録と突き合わせた。
- 2026-10-25 21:00〜10-27 00:00（27 時間）: **15 件すべて同じ足・同じ値段で入り、決済の理由も一致**。R の差は保有コスト（記録は差し引く・執行は業者のスワップ）と SL/TP の桁丸めだけ。
- 注意した点: H4/D1 の特徴量（`M.mtf_feats`）は「同じ区切りの足がまだ続くか」で前の区切りを選ぶので、確定足だけで計算すると判断が変わる。執行では**今できている足の時刻を「場つなぎ」の 1 行**として足してから判断する（`execute_mt5.bars()`・`signal_s21.decide()` の注記）。休み（週末・祝日）の直前の足だけは一致しない（記録は休みを知っている・執行は知らない）。

## winnote での初回（2026-10-28）

- `--once`（dry）で XM デモ（XMTrading-MT5 3・equity 100 万円）に接続・19 銘柄すべて取得・合図 2（USTECH 買い・JPN225 売り）。
- 直した点 2 つ（Mac の正本にも反映済み）: ① Windows の LightGBM が日本語パス（`凍結\model_a0.txt`）を開けない → `signal_s21.py` でモデルを Python で読んで文字列で渡す ② XM は CFD（GOLD・US500Cash・US100Cash・GER40Cash）の `trade_tick_value` を**損益通貨のまま**返す（FX は円換算済み）→ ロットは「D × 契約サイズ × 損益通貨→円」で計算（`lot_for`）。直す前は USTECH が 2.7 lot（equity の約 6%）になっていた。
- equity 100 万円・0.04% だと 金・US100・GER40 などは最小ロットに張り付く（USTECH 0.1 lot＝リスク約 2,300 円）。デモなので R の記録には影響しない。台帳の note に「最小ロットに切り上げ」が残る。

## 乖離の見方（毎週）

1. `compare_record.py` で「同じ判断の足」の一致率（目標 95% 以上・XM 照合の 98.7% が目安）
   - 2026-11-10 追記: 「同じ足で入った率」は同時 1 本・週 10 回の規則で 1 回のずれが後ろへ連鎖するので、95% には構造上届かない（今の版で 37.5%）。足の差（XM と Dukascopy）そのものは **「合図の一致」**（記録が入った足で bot も同じ向きの合図を出したか・bot のログから読む）で見る。今の版で 73%（11-04 16〜11-09 22 UTC・37/51）。`compare_record.py` と `状態.md` の照合の行に出る
2. 一致した取引の R の差（スプレッドと滑り）。規程 §4 ③「実測コストが 1R の 3% 以内」はここで測る
3. `ログ/` の毎時の行の抜け（PC の稼働率）。抜けが月 5% を超えるなら AWS を検討

（2026-10-31〜）1 と 3 の材料は `send_status.py` が毎時 Mac に送り、照合は `自動実行/状態.md` の「執行（winnote）」に毎回出る。
