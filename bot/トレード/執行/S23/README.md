# トレード/執行/S23 — S23（BTC・ETH の日足の上昇トレンド買い）を MT5 で動かす（2026-11-18 案・Opus 5.5 の自走）

`forward/S23` が「Binance の足で保有を計算して率を記録する」のに対し、ここは **同じ判断で XM の MT5 に実際に注文を出す**層。最初は S21 と同じ XM の MT5 デモ口座で動かし、記録との差（入口・出口の値段・スワップ）を測る。

## 決めたこと（2026-11-18・Claude・入れる前の案）

| 項目 | 決定 | 理由 |
|---|---|---|
| 判断 | `signal_s23.py` が **記録のプログラム `forward/S23/forward_s23.py` の main() をそのまま**走らせ、出てきた 状態.json の「次の売買日の保有」を目標にする。足の置き場所と出力先だけ一時フォルダに替える | 判断の計算を書き写さないので、記録と執行のずれは「足を取った時点」だけ。停止線（最高値から −30%）も記録と同じ計算 |
| 判断の足 | 記録と同じ Binance 現物の 1 時間足（`forward_s23.fetch` を置き場所だけ替えて呼ぶ。置き場所は `S23/足/`・記録の `market_data_forward/crypto_h1` には書かない） | S21 は業者の足で判断するが、S23 は日足で 60 本前と比べるだけなので、業者の足との差は小さい。代わりに毎回 **業者の H1 でも同じ判断を出して「照合」の行**に残す（判断には使わない） |
| いつ動く | 毎時 :01:00（起動の直後・例外で繋ぎ直した後もすぐ 1 回）。目標と建玉が違えば成行で入る／閉じる。**金 21:00〜日 21:00 UTC（記録の取引時間の外）は何もしない**。Binance の最後の確定足が 1 時間より古い回・前に動いた判断の日より古い日の目標では動かない | 記録は「その日の終値で決め、次の始値（21:00 UTC・週末なら日曜 21:00）で入る」。毎時見るので、PC が止まっていた日も次の回で追いつく（遅れは照合の「入口の遅れ」に出る）。:01:00 は PC の時計が進んでいても締まる前の足を使わないため |
| 出口 | 目標が 0 になった日の次の始値で成行。SL・TP は置かない | 記録に損切りは無い（Q529 で損切りは悪化） |
| 停止 | 記録と同じ計算で最高値から −30% に達したら全部閉じ、`停止.flag` を書いて以後は入らない。記録の「最高値から」は全期間の最小なので、一度達すると記録も止まったまま＝**bot も戻らない**（flag を消しても次の回で書き直す。再開は規程を変えて別 ID にするとき） | 規程 §6 の S23 の停止条件 |
| 量 | 1 銘柄の名目 `notional_per_coin`（既定 15 万円＝元手 30 万円の半分）。最小ロット未満は最小ロットに切り上げて台帳の note に残す | 記録は「半分ずつ・名目 1 倍」。比べるのは率なので額に依らない。BTCUSD の最小 0.01 ロット ≒ 12 万円（11-01 の値段） |
| S21 との同居 | magic 215023（S21 は 215021）。S21 の「合計 12 本」「1 銘柄 1 本」は S21 の magic だけを数えるので、S23 の建玉は S21 の判断に効かない。証拠金だけは共有なので、入る前に **必要証拠金 ≤ 余剰証拠金 × 0.3** を確かめ、足りなければ ★ で見送る | — |
| 既定は dry | `--live` を付けない限り発注しない。`--live` には config の `expect_server` が要る（つないだ先の取り違え防止）。実口座につながっていたら止まる。同時に 2 つは動かない（`実行中.lock`） | S21 と同じ＋点検 7・8 |
| 約定の確かめ | 発注の返事でなく**建玉が現れたか**で決める（返事が失敗・無しでも約定している形、PLACED でも約定しない形がある）。台帳に無い自分の建玉は取り込み、台帳で開いているのに建玉も約定も無い行は void。部分約定は約定した量を台帳に。手で閉じた建玉は、目標が 1 のままなら次の回で入り直す（記録に合わせる） | 点検 1・3・13 |
| 起き直し | 発注が通らない・足が古い回は 5 分後（同じ時間の中だけ）。自動売買オフ・資金不足・取引不可（10027・10019・10017）は起き直さない。許容滑りはその時のスプレッドの 1 倍（BTC と ETH で幅が釣り合う） | 点検 9・10 |

## XM で動かすときの注意（2026-11-01 の仕様の CSV・`s23-crypto-uptrend-long-q529/results/swap_from_mt5.json`）

- **買いのスワップが 1 晩 約 0.069%（年 約 25%）**（BTCUSD −5370.2 ポイント・ETHUSD −155.8 ポイント）。記録は保有コスト 0（Fintokei の形）で計算している。開発期間の感度では、年 25% でシャープ 0.88 → 約 0.6。S23 の保有は 6 割弱の日なので、記録より年 十数 % 下がる見込み。**XM での執行は「日足の執行と照合の練習」で、XM の S23 の損益をエッジの証拠として読まない**（S21 の Q751 と同じ扱い）。
- スプレッドは 11-01 の値で BTC 往復 約 0.05%・ETH 約 0.13%（記録の片道 0.02%・0.075% とほぼ同じ）。
- XM の暗号資産 CFD の取引時間（週末に動くか・日曜 21:00 UTC に開いているか）は未確認。開いていなければ注文が通らず、5 分おきに起き直す（遅れはログと照合に出る）。初回の `--once` で確かめる。

## winnote で動かす手順（承認の後・15 分）

1. Mac: `python3 deploy_s23.py` → lab-ops の `trade/S23_bot_YYYYMMDD.zip` を commit・push（人）。
2. winnote: `cd C:\Users\gtaic\lab-ops; git pull` → zip を `C:\Users\gtaic\bot\` に展開。
3. `cd C:\Users\gtaic\bot\検証\トレード\執行\S23; python execute_s23_mt5.py --once` → 「接続: XMTrading-MT5 3（デモ）」・銘柄 `{'BTC': 'BTCUSD', 'ETH': 'ETHUSD'}`・「照合」の行が出れば OK。
4. 1 日 dry で `--loop` → ログを見る → `--loop --live`（タスクスケジューラで「ログオン時」・タスク名 S23_bot。S21_bot と同じ形）。
5. `send_status_s23.py` を 1 時間ごと（タスク名 S23_send_status）。

## 記録との乖離の見方

- 「照合」の行: 記録の足（Binance）と業者の足（XM の BTCUSD）で判断が違う日があれば ★。
- `compare_s23.py`: **記録の保有の区間**ごとに、bot が同じ判断の日に入ったか（取りこぼし）・入口の遅れ・入口の差（正＝高く買った）・出口の差（正＝安く売った）・スワップ率・超過コスト（正＝bot のほうが損）・区間のずれ（手で閉じた等）。記録に無い bot の保有も数える。保有は年に数回なので、本数がたまるのは遅い。

## 点検（2026-11-18・別の目・Opus）
13 点の指摘（重いもの: 返事が失敗でも約定した建玉が台帳に載らない・Binance の足が途中までだと前の日の判断に戻る・PLACED の後に台帳の行が開いたまま残る・例外の後と起動の直後に回が飛ぶ・照合が bot の行だけを回す）は全部直し、試験を足した（`test_s23.py` 38/38）。直していないもの: なし（13 の「手で閉じると入り直す」は記録に合わせる作りとして README に書いた）。

## 2 回目の点検（2026-11-18・別の目・Opus）
売買の流れに「入るべき日に入れない・永久に止まる」形は無し。12 点を直した: 動いている途中に実口座へ替わったら止める（毎回の確かめ）／照合は区間 [d, e) に判断の日がある行を結ぶ（遅れて入った・入り直し・取り込みも取りこぼしにしない）／発注の控えで、取り込んだ行に正しい判断の日と名目、返事が失敗でも閉じていた決済に理由と出る日を付ける／相殺（OUT_BY）なども出口とみなす／建玉の一覧が取れない回は「閉じた」とみなさない／live の配備は --once で繋がったデモのサーバー名を expect_server に書く／zip の失敗を見逃さない（pipefail）／dry の間は目標と保有の差を ★ にしない／判断の足は「今 − 60 秒」で切る（時計の進み）／照合も締まっていない最後の日を落とす／配る前に mt5_fetch も S21 の版と比べる。「ログオン時」のタスクを台本から作れるかは配る日に確かめる（断られれば rc 5 で止まる側）。
